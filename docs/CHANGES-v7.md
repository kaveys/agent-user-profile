# v7 — 让画像真正参与决策，而不只是「背景知识」

## 问题

旧注入块第一句写的是「背景知识，不是本轮指令」。这句话本意是防止画像压过用户当下的指令，实际效果却是**画像永远只是个参考**：模型扫一眼，然后照自己的默认套路写界面、定风格、选默认值。用户说的「以画像为主要参考依据」在提示词层面根本没有落点——它只被写进了文档，没被写进模型真正读到的那段文字。

## 三条改动

### 1. 注入块从两段改成三段，并写明使用顺序

```
# 用户画像 vNN
> 生成于 … · 共 X 条，本次带入 Y 条（红线 a · 个性化 b · 参考 c）
> 使用顺序：本轮明确指令 > 红线 > 个性化首选 > 背景参考。
> 涉及风格、口味、默认选择、文案、推荐、界面时，以个性化首选段为主要依据；画像里有答案的事直接按它办，不要反问用户。

## 一、红线与硬要求（任何时候都遵守；与本轮指令冲突时先说明，再按本轮执行）
## 二、个性化首选（涉及风格/口味/默认选择/文案/推荐/界面时，以这些为主要依据）
## 三、背景参考（按权重排序，用来减少反问、定默认值）
```

三段各有预算帽：红线 40%、个性化 75%、其余吃满 `maxChars`。这样条目涨到几百条时，红线和「个性口味」都不会被截断砍掉。

「个性化首选」段来自 `inject.personalizeDimensions`（默认 `taste / communication / habits / interests / goals`）——这几个大类回答的正是「他喜欢什么样、他要我怎么说、他什么节奏」，个性化决策只能靠它们。

### 2. 识别「这一轮确实需要个性化」，并在提示词里升级画像的地位

`isPersonalizeTurn(text)` 对用户本轮的文本做模式匹配（`inject.personalizePatterns`，默认 23 条：个性化/风格/调性/审美/好看/配色/视觉/排版/界面/布局/文案/措辞/语气/口吻/按我的/照我的/我喜欢/推荐/选型/默认/偏好/口味/定制/适合我…）。命中时注入块的首段换成：

> 本轮属于需要个性化的需求：**画像里「个性化首选」段是选方案、定风格、定默认值、写文案的主要依据**，不是可有可无的背景。
> 优先级：本轮明确指令 > 红线与硬要求 > 个性化首选 > 背景参考；与代码/文件/数据中的可见事实冲突时，以事实为准。
> 画像里已经有答案的事（风格、口味、习惯、边界）直接按它办，**不要再反问用户**；确实需要新信息时，只问画像里没有的那一点，并说明为什么要问。

最后那句是这版最实用的一条：**画像存在的一半价值是让人少被问一遍**。以前模型知道用户喜欢简洁界面，仍会问「你要什么风格？」——现在这句被明确禁止。

### 3. 面板暴露这个开关，并说明当前档位

- 设置页「画像怎么被使用」新增：**个性化需求时以画像为主要依据**（`inject.priorityOnPersonalize`，默认开）。关掉后退回「全部按权重排」的老形态。
- 概览「当前策略」新增一行：`个性化需求 → 以「个性化首选」为主要依据 / 只当背景参考`。

## 配置变化

`schemaVersion` 3 → 4。新增三个键（老配置自动补齐，并留 `config.json.bak-v3-*`）：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `inject.priorityOnPersonalize` | `true` | 是否单列「个性化首选」段并按它决策 |
| `inject.personalizeDimensions` | `taste, communication, habits, interests, goals` | 哪些大类算「个性化依据」 |
| `inject.personalizePatterns` | 23 条正则 | 判定本轮是否需要个性化 |

## 未做

- 不做「画像与实践冲突时自动改画像」。冲突只能由人裁决（`edit` / `review`），自动改写会让画像自我漂移。
- 不按轮次衰减个性化权重。衰减的副作用是「用久了就不个性化」，与本次目标相反。
