# v20：第五轮排查 + 画像健康度 / 能见度命令 / 面板宿主信息

日期 2026-11-17 · 提交见仓库历史

这一轮不是加功能，而是把「插件自己说的话」和「插件实际做的事」对齐，并给用户两个以前只能靠问才能得到答案的东西：画像现在健康吗、这台宿主到底支持什么。

## 一、第五轮排查（`_audit5.mjs`，31 项）

前四轮分别打边界、往返、逻辑一致性、宿主兼容。这一轮专打**漂移**：同一个事实在两处各说一套。

| 段 | 打什么 | 举例 |
| --- | --- | --- |
| A | 面板渲染的每个可编辑字段都能用 `set` 改 | 发现 `redaction.patternCount` 只在面板里出现，`set` 白名单里没有 |
| A2 | 同一套算法在两处必须给出同一个结论 | `explain` 说无关、注入却带入了 —— 分母不同 |
| B | 计数自洽 | 三类分区条数之和 = 条目数；`stats.items` 与列表长度一致；每项都带 `partition`、`provenance` |
| C | 健康度语义 | 五项齐全、`total` 等于五项和、30 天不重建新鲜度必须归零、重建后必须回满 |
| D | 相关性语义 | `--json` 可解析、`carried + dropped` 等于全部、红线维度即使无关也带入 |
| E | 数据脏 | `declarations.jsonl` 混进坏行时，面板仍可用并提示「有损坏」 |
| F | 命令契约 | 未知命令 / 未知键 / 越界必须非零退出；`forget` 无匹配非零；`export` 到目录成功 |

### 修掉的三个真缺陷

1. **`settings.redaction.patternCount` 是不可写的派生值**。面板把它当配置渲染，`set` 却不认它 —— 用户在面板上改不到、脚本里改不动。修法：`settings` 只留可编辑字段（`mode`、`presets`），派生计数移到 `redactionInfo`。
2. **`explain --json` 永远解析失败**。原实现先打文本再打 JSON，`JSON.parse` 拿到一整屏中文。修法：`--json` 时只输出 JSON 并 `return`。
3. **`stats.history` 的类型在两次迭代里从数组变成数字**，面板和脚本各读一套。修法：`stats.history` 固定为数字（条目数），明细数组固定叫 `historyItems` 放在 payload 顶层，并在测试里钉死这两个名字。
4. **相关度算错了分母**。原来用「命中二元组 ÷ 条目二元组总数」——条目越长越吃亏，于是「用户要求界面像成熟产品：有层次、有留白、文案面向用户…」这种明明该命中的长条目只算 4%，被 `explain` 判成无关；而真实注入（只要有一个二元组就留）会带入它。两处说法不一致，用的还是同一套算法。修法：分母改成查询的二元组总数（命中 ÷ 查询规模），语义变成「这句话被这条条目覆盖了多少」，与实际注入行为对齐：同一查询下该条 4% → 25%，被正确带入。

## 二、两个新命令：让「能不能用」可以被查

### `profile explain "<这句话>"`

回答「这次对话会用到哪些条目」。用与注入同一套字符二元组算法复算相关度（`relevanceFloor` 默认 0.12），输出：

```
本次会带入的条目（7/18）
- [审美与口味 0.90] 相关度 25% :: 用户要求界面像成熟产品…
- [约束与红线 0.90·红线] 红线维度，永远带入 :: 用户要求对外上传前必须彻底脱敏…

被相关性挡掉的条目（12）
- [能力与工具 0.8] 用户做 Android APK 逆向…

判定规则：核心/红线维度永远带入；其余相关度 ≥ 12% 才带入，挡掉不等于删除。
```

`--json` 给 `{carried, dropped, threshold}`，便于脚本核对。

### `profile health`

五项各 20 分，给出总分与短板建议：

| 维度 | 扣分规则 |
| --- | --- |
| 新鲜度 | 按 `builtAt` 距今天数，每天 −2（无 `builtAt` 时退回 `profile.json` 的 mtime） |
| 覆盖度 | 有条目的大类数 × 2 |
| 精度 | 含高风险隐私的条目每条 −4 |
| 一致性 | 未决冲突每条 −4 |
| 重点明确 | 核心条目 × 4 |

真实数据实测 96/100（一致性扣 4 —— 有一条被取代的旧值留着）。`--json` 给结构化结果，面板概览直接画这张卡。

## 三、面板新增两块

- **概览 → 画像健康度**：总分（24px）+ 五项条形 + 首条建议。低于六成的那项转黄色。
- **备份与重置 → 宿主能力**：从 `.host.json` 读这台宿主的能力，六项「可用 / 缺失」，附最近诊断 6 行。没有记录时给一句「重启一次 dsh 后会自动写入」，而不是空着。

`panel.json` 相应多出两个键：`health`（五项 + 总分 + 建议）、`host`（`caps` + `diagTail` + `capsPath`）。

4. 相关度没有同义词表：命中必须共享二元组，「好看」对「美观」仍算无关。
