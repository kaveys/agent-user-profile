# v25 —— 相似的记忆主动合并

一句话：**同一件事不攒第二条**。写入时并、整理时并、字面不像的交给模型判一次再并；并错了进快照，能整批还原。

## 为什么现在才做对

v24 之前的去重只有一层：`build` 阶段按字符二元组 Dice、阈值 0.45、且只比同一个大类。三个限制叠起来，实际几乎不生效：

| 真实条目对（画像里同时存在） | Dice | 包含度 | 综合分 | 旧逻辑 | 现在 |
|---|---|---|---|---|---|
| 用户要求界面简洁，不要花哨动画 / 界面要简洁，别整那些花哨的动画效果 | 0.29 | 0.31 | **0.44** | 放过 | 合并 |
| 用户要求不同插件职责分离，功能不要混在一起 / 不同插件职责分离，功能不要混在一起 | 0.36 | 0.38 | **0.56** | 放过 | 合并 |
| 上传前必须彻底脱敏… / 对外公开内容前必须彻底脱敏（…） | 0.59 | 0.67 | **0.67** | 放过 | 合并 |
| 口味偏好 vs 习惯（不相关） | 0.11 | 0.13 | 0.13 | 放过 | 放过 |
| 身份 vs 技术栈（不相关） | 0.07 | 0.13 | 0.13 | 放过 | 放过 |

实测把「同义改写」和「不相关」分开了：同义落 **0.38–0.67**，不相关 ≤ **0.14**，中间是空的 → 阈值从 0.45 下调到 **0.35**，两边都有余量。探针脚本跑完即删（`_probemerge.mjs`）。

## 四层，从便宜到贵

| 层 | 触发 | 判定 | 代价 |
|---|---|---|---|
| 1 完全相同 | `declare` | 同 dim+key+scope+原话 → 更新那一条 | 无需模型 |
| 2 字面相似 | `declare` / `build` / `dedupe` | `mergeScore ≥ 0.35`（同大类）、`≥ 0.8`（跨大类） | 纯计算 |
| 3 语义同义 | 轮末自动 / 面板「让 AI 判同义」 | 模型读候选对，只回 `same=true` | 一次小模型调用，30 分钟最多一次 |
| 4 人工判 | 面板/CLI 手选 | `merge --keep --drop` | 人工 |

### 判定分怎么算

```
similarity(a,b)  = 字符二元组 Dice
coverage(a,b)    = 短句的二元组有多少被长句覆盖     ← 抓「一句话被另一句整体包含」
similarScore     = max(similarity, coverage)
stemText(t)      = 去掉「用户/我 + 要求/习惯/喜欢/是/在…」主语前缀
mergeScore(a,b)  = max(直接, 去主语后)
```

三道守卫，防止「合并」变成「丢信息」：

1. **数字守卫**：两句的数字集合不同（班级、年份、版本、数量）→ 一律不同义。否则「第 1 条/第 2 条」「262 班/263 班」会被并掉。
2. **同 key 不并**：同大类同 key 的不同说法是「覆盖/冲突」，交给 `conflicts` 与 `history` 留痕——否则「偏好深色 → 偏好浅色」会变成一条，且看不出改过。
3. **跨大类更严**：阈值 `max(0.8, 同类阈值 + 0.3)`，只有措辞几乎一字不差才跨类合并；避免把「习惯上要简洁」和「口味上偏好简洁」揉成一条、丢掉分类。

### 合并后保留谁

- 正文取**更可信那条**（`confidence` 高者）的措辞；一条几乎被另一条完全包含（`coverage ≥ 0.92`）时取信息更全的长句。
- 权重取两者最大，`core` 取或。
- 落败的原话进 `mergedFrom: [{id, dim, fact, judged?}]`；`build` 阶段的合并在 `conflicts` 里记 `status:'merged'`，落败条目进该大类的 `history`。
- 每次批量合并前 `snapshotDeclarations('dedupe')`，面板「备份与重置 → 恢复点」可整批还原。

## 怎么用

```bash
dsh-profile dedupe                      # 预览：哪些会并成哪条（不动数据）
dsh-profile dedupe --apply              # 落库（先留快照）
dsh-profile dedupe --threshold 0.5      # 更保守
dsh-profile dedupe --pairs              # 导出候选对 JSON，给模型/人判
dsh-profile dedupe --apply-pairs "keepId|dropId,keepId2|dropId2"
dsh-profile declare --dim taste --fact "…" --no-merge   # 就是要单独存一条
```

- 面板：条目页「合并相似条目」（两段式：先预览、再确认）、「让 AI 判同义」。
- MCP：`profile_dedupe { apply, threshold }`。
- 自动：每轮结束先 `extract`，再按间隔（`build.semanticMergeIntervalMs`，默认 30 分钟）判一次语义同义；`build.autoMergeSemantic: false` 可关。

## 配置

| 键 | 默认 | 含义 |
|---|---|---|
| `build.dedupe` | true | 是否做字面去重 |
| `build.similarityThreshold` | **0.35** | 同大类判同义的门槛 |
| `build.autoMergeSemantic` | true | 轮末是否让模型判一次语义同义 |
| `build.semanticMergeIntervalMs` | 1800000 | 语义合并最小间隔 |

`config.json` 升到 **schemaVersion 6**：老配置里我们自己的旧默认 0.45 自动迁到 0.35（不是用户选的，不清掉新默认永不生效）。

## 修掉的真 bug

1. **合并后留下低权重措辞**：新条目 0.9、旧条目 0.45，合并却保留旧的 → 改为按可信度取措辞。
2. **数字不同的条目被并**（并发写用例 4 → 5 暴露）→ 加数字守卫。
3. **同 key 覆盖被相似合并吞掉**（`_audit2` 的「覆盖会留下冲突/历史痕迹 — conflicts=0」抓到）→ `declare` 与 `dedupe` 都跳过同 dim+同 key。
4. **面板 async 动作序列化成 `{}`**：`finish(handler(input))` 不等 Promise，语义合并这种异步动作会返回空对象 → 改为识别 thenable。

## v25.1 追加：低线索轮不许把画像挡空

真实翻车现场：用户说「这个是对的，你要在思考的时候主动思考会不会用到其中的几条信息并且调用」，相关性闸门按字面判出来 0 条命中 → **19 条偏好全被挡在外面**，注入块里只剩红线，画像在这轮等于没生效。而这轮恰恰最需要「真机跑通」「界面要成熟」「短句直给」这些条目。

修法：给闸门加**按权重保底**，只看「可筛条目」（非红线段）：

```
floor = min(12, max(2, ceil(可筛条目数 × 0.6)))
命中的条目 < floor 时，从被挡条目里按权重补足，单列一段：
## 保底带入（本轮字面无关，按权重补足）
```

实测（真实 25 条画像，直接调 `agent/pre-step`）：

| 本轮用户输入 | 带入 | 未带入 |
|---|---|---|
| 这个是对的，你要在思考的时候主动思考… | **18 条**（含保底段） | 7 |
| 帮我把面板的删除按钮改成两段确认 | 25 条 | 0 |
| 给宣传片换个配音 | 18 条（含保底段） | 7 |

取舍：宁可多带 6 条，也不要在一个「继续」把画像变成空壳；保底段显式标注来源，模型能分清「因为相关」还是「因为重要」。环境变量 `DSH_PROFILE_MIN_KEEP` 可调上限（默认 12）。

连带修测试：`tests/selftest.mjs` 的相关性用例先把画像撑到 6 条以上再测（否则保底覆盖全部条目，测不出闸门在筛），并新增两条低线索轮断言；`tests/audit-4.mjs` 的「无关条目被挡在外」放宽为「要么被挡，要么被明确标成保底带入」。
