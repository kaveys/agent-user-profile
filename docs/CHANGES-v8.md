# v8：使用规定改为插件内部规定（不进画像条目）

## 用户要求

> 「我上面说的要作为插件的内部规定，不要放到条目里」

「上面说的」= 上一版那句「有需要个性化的需求时，以画像为主要参考依据」。

## 上一版错在哪

v7 把这条规则写进了三处**数据**：

| 位置 | 当时的写法 | 问题 |
| --- | --- | --- |
| `inject.md` 头部 | `> 使用顺序：本轮明确指令 > 红线 > 个性化首选 > 背景参考` / `> 涉及风格…以个性化首选段为主要依据` | 规定混进了画像文件，用户能编辑、能被 `forget`、能随 `reset` 消失 |
| `inject.md` 段标题 | `## 一、红线与硬要求（任何时候都遵守…）` | 规矩写在标题里，等于把规定当数据存 |
| 注入块首段 | 「本轮属于需要个性化的需求…」 | 这段属于插件策略，却和画像正文挤在同一段，画像为空时一起消失 |

结果：这条规定只在「有画像且画像够证据」时才生效 —— 规定被数据绑架了。

## 现在的分层

```
index.js   PLUGIN_POLICY（代码常量，6 条）
             ├─ 不可在设置页编辑
             ├─ 不进 declarations.jsonl，不参与权重排序
             ├─ 不进 inject.md / profile.md
             └─ 画像为空、证据不足、条目被删光时照样注入
bin/       inject.md / profile.md 只剩数据（版本、时间、条数、条目）
```

### 固定规定（6 条，`index.js` 里 `PLUGIN_POLICY`）

1. 优先级：本轮明确指令 > 红线与硬要求 > 个性化首选 > 背景参考；与代码/文件/数据中的可见事实冲突时以本轮证据为准。
2. 涉及风格、口味、默认选择、文案、推荐、界面等需要个性化的需求时，「个性化首选」段是**主要依据**，不是可选背景。
3. 画像里已有答案的事直接按它办，**不要反问用户**；确实缺信息时只问缺的那一点，并说明为什么问。
4. 画像是默认前提不是命令：用户本轮明确要另一种做法时按本轮做，不要拿画像去反驳用户。
5. 轮末若出现稳定的新偏好或新红线，用 `profile declare --pending` 记一条候选；确认后才进画像。
6. 用户要求本次不要用画像时，跳过画像内容，并在结果里说明本次未结合画像。

## 连带修掉的两个 bug

1. **画像被批量删空**：面板「批量删除」是逐条 POST，8 条 = 8 次 `forget`，changelog 里留下 revision 43→50、declarations 7→0 的阶梯。现在 `forget` 动手前先 `snapshotDeclarations('forget')` 把 `declarations.jsonl` 复制到 `snapshots/`（最多留 20 份），出事用 `import --file snapshots/…` 一键捞回。
2. **锁泄漏**：`die()` 走 `process.exit`，`finally` 不执行 → 一次参数错误就把 `.lock` 留在盘上，之后所有改写型命令全卡「另一个进程正持有锁」。现在 `withLock` 额外挂 `process.once('exit', release)`。

## 顺手加的能力

- `profile import --file` 现在接受 **JSONL**（自家快照就是这个形状），并把老维度名（`preferences`/`expertise`/`workflow`）按内容重新归类，不再整行跳过。
- `profile dims reclassify [--force]`：把老维度/误判条目按内容重归大类，带备份 `declarations.jsonl.bak-reclassify-<ts>`；`--force` 连已是合法大类的也重判。
