# v24：从别的 AI 搬回画像

## 要解决的问题

用户换工具时，新助手对他一无所知；而旧的那个其实已经攒了一堆关于他的判断。让用户去别的 AI 问一句「你掌握了关于我的什么信息」，把那堆文字搬进来，本插件负责把它变成**结构化的、有权重的、可编辑的**画像条目。

三个角色分工明确：**别的 AI 给素材，本插件给结构，用户给最终裁决**。

## 一条命令

```bash
dsh-profile ingest --file chatgpt-about-me.txt --source ChatGPT          # 预览
dsh-profile ingest --file chatgpt-about-me.txt --source ChatGPT --apply  # 落库
```

也可以 `--text "整段答复"` 直接贴；面板在「备份与重置 → 从别的 AI 搬回来」；MCP 客户端用 `profile_ingest`。
默认**只预览**：写库是不可逆动作里最容易被点错的一类，先看再写。

## 处理链路

| 阶段 | 实现 | 判据 |
| --- | --- | --- |
| 切分 | 去列表符号（`- ` `1. ` `（1）` `一、`）→ 按行切；行长 > 120 字按中文句读切；≥ 18 字且前后半句归到不同大类的，拆成两条 | 别的 AI 常把两件事写进一句（「习惯晚上工作，通常先给结论」） |
| 去噪 | 丢弃 < 4 字、> 400 字、Markdown 标题、表格分隔线、「以下/以上/暂无/仅供参考/作为 AI」开头的句子 | 客套不是画像 |
| 人称 | 句首「你/您」→「用户」，句中「你的」→「自己的」 | 画像会被注入 prompt，主语错位会让模型以为在描述别人 |
| 归类 | 固定优先级表逐条匹配关键词，第一条命中的大类胜出：沟通与表达 → 约束与红线 → 审美与口味 → 习惯与节奏 → 目标与计划 → 能力与工具 → 学业与职业 → 身份与背景 → 兴趣与爱好 → 关系与协作 | 可解释：报告里写「命中『不希望』」，用户能自己核对 |
| 定权 | 0.55 起步；硬性要求 +0.15、稳定特征 +0.10、同批佐证 +0.05、含糊措辞（可能/据说/大概）−0.12；夹在 **0.35–0.85** | 二手转述不该和你亲口说的话同权 |
| 红线 | `constraints` 且命中硬性要求 → 权重抬到 0.85 并标核心 | 边界比偏好重要 |
| 隐私 | `blockedPrivacy` 命中证件号/银行卡/密码/精确住址 → 整条不收；手机号/邮箱/密钥 → 打码后收 | 「记着他有身份证号」本身没有画像价值，留着只有风险 |
| 去重 | 与现有条目相似度 ≥ 0.75 视为已有（跳过，报告里列出来）；0.45–0.75 复用它的 key → 导入时并进那一条 | 同一件事不该攒出五条同义条目 |
| 溯源 | 每条写 `provenance: { kind:"import", source:"ChatGPT", excerpt:前 80 字, at }` | 面板能区分「模型提炼 / 你亲口说的 / 别处搬来的」 |

## 报告长什么样

```
来源：ChatGPT　候选 8 条 → 可写入 7 条

## 沟通与表达（1 条）
- [0.70] 用户希望回答简短直接，不要废话，最好带证据
    依据：硬性要求 +0.15，命中「回答」

## 约束与红线（1 条）
- [0.85] 用户不希望别人修改自己的项目文件夹，也不能删自己的数据（核心）
    依据：硬性要求 +0.15，命中「不希望」

## 跳过的条目
- 画像里已有（相似度 ≥75%） 2 条：用户是一名本科在读学生… 等
- 疑似隐私，不收录 1 条：我的证件号是 1101…
```

预览与落库用的是同一段代码，所以「看到什么」＝「写进去什么」，不存在两份逻辑。

## 本轮修掉的四处逻辑问题（都是自测抓出来的）

1. **`你好` 类第二人称没转**：「你是一名本科生」原样入库，注入时像在描述别人 → 加 `normalizeVoice`。
2. **`希望` 被当成目标**：「不希望别人改我的文件」落到 `goals` → `goals` 正则去掉 `希望/想要`，`constraints` 补 `不希望/别让/别再`。
3. **红线吃掉表达习惯**：「回答简短，不要废话」被判成 `constraints` 核心 → 优先级表把 `communication` 提到 `constraints` 之前。
4. **拆句丢失主语**：拆出来的「也不能删自己的数据」是半句话 → 去连接词 + 自动补「用户」。
